## 1. Scope

**In scope (MVP)**

1. **MCP for the user's agent.** New tools in the existing `screenpipe-mcp`
   package that read the journal and focus state and set the current intention.
2. **Daily journal.** Read-only. Today / date selector → day overview →
   activity cards → source evidence. Generated by an engine-owned background
   worker and persisted in SQLite through `screenpipe-db`.
3. **Distraction detection.** Retrospective classification of every journal
   card (activity type + relationship to the user's stated intention), plus a
   near-real-time "focus state" over the last few minutes. Detection is the
   deliverable; a notification nudge is a thin, off-by-default layer at the end.

**Out of scope (explicitly)**

- Editing the journal: rename, recategorize, split, merge, project assignment.
  The schema reserves columns for it, no UI or API is built.
- Chat with the journal, search UI, weekly review, standup, Markdown export.
- Any automatic intervention (closing tabs, quitting apps), desktop pet, scores.
- Porting Dayflow's SwiftUI or its pixel-based (video → Gemini) transcription.
  Screenpipe already has text evidence; only prompt logic, validators,
  classification rules, output formats and test cases are ported.

**Out of the plan, decide separately:** this working tree is post-relicense
`main` (Screenpipe Commercial License, `f390fa9d2`). The brief lists the
options (fork the MIT snapshot, buy a license, or reuse only MIT-era crates).
Nothing below depends on the answer, but it must be settled before shipping.

## 3. Architecture decisions

1. **Engine-owned, not app-owned.** Worker, storage and routes live in
   `screenpipe-engine` + `screenpipe-db`. Reason: MCP talks to `localhost:3030`,
   the CLI must work without the desktop app, and writes must go through the
   coordinator (`WriteOp` or `begin_immediate_with_retry`). Mirrors the
   activity-ledger commit `a657795889` file layout exactly.
2. **Compile deterministically, then one structured LLM call per window.**
   Not a Pi/ACP agent run. Input is the ledger's task-depth intervals plus a
   bounded text sample; output is JSON validated by ported Dayflow rules.
   Reason: bounded cost, offline with Ollama, testable with golden fixtures,
   no agent flakiness (see `meeting_summary/mod.rs` header for why that matters).
3. **LLM provider = the user's OpenAI-compatible preset.** Reuse
   `resolve_ai_preset` + `upstream_for`. Supported for MVP: `native-ollama`,
   `openai`, `custom` (DeepSeek or any OpenAI-compatible URL). `screenpipe-cloud`
   goes through `cloud_proxy.rs`. `acp`/`pi` presets are rejected with a clear
   settings message. New setting `journalAiPresetId` (pattern:
   `activitiesAiPresetId`).
4. **Dayflow window model, screenpipe evidence.** Windows target 15 min, split
   on a > 2 min gap, context = last 45 min of cards + new observations, cards
   10–60 min, detours < 5 min recorded as `distractions[]` inside a card.
   Cards for the trailing 45 min are rewritten on each run ("a draft you're
   revising"), so a card only becomes `final` once its end is older than the
   rewrite horizon.
5. **Two classification axes, kept separate** (roadmap §1 of the Drifty
   section): `category` = activity type from a user-editable list (seeded from
   Dayflow's role presets); `intention_relation` ∈ {`supports_intention`,
   `other_work`, `break`, `possible_distraction`, `unknown`}, only computed while
   an intention is set. Missing evidence yields `unknown`, never distraction.
6. **Retrospective before live.** Card-level classification ships first. The
   live tail detector persists a `focus_state` row and surfaces it in the tray
   tooltip, the journal "now" strip and MCP. A notification nudge is gated by a
   setting that defaults to off and by the roadmap's conditions.
7. **Time is estimated and computed one way.** Active minutes use the
   `IDLE_CAP_SECS` gap-sum from `/activity-summary`. Cards carry
   `active_minutes` labelled as estimate; wall-clock span is separate. Audio is
   never added to screen minutes. A single shared constant module replaces the
   two independent idle constants.
8. **Day boundary is local 04:00** (Dayflow), configurable later. Timestamps are
   stored UTC RFC3339 like the ledger.
9. **Privacy boundary = capture boundary.** Redacted frames
   (`*_redacted_at` columns) contribute no text; history-access policy clamps
   every journal read like `apply_activity_ledger_history_access`; deletion of
   source rows cascades into journal evidence via triggers mirroring the
   ledger's. The prompt text sent to the provider is logged to a bounded
   `journal_runs` table so the user can see exactly what left the machine.

## 4. Data model (new migration in `crates/screenpipe-db/src/migrations/`)

```
journal_windows        -- unit of work for the worker (Dayflow analysis_batches)
  id, start_at, end_at, status CHECK IN ('pending','processing','done',
  'failed','skipped_short','idle'), attempt INTEGER, evidence_hash TEXT,
  prompt_version TEXT, model TEXT, error TEXT, created_at, updated_at
  UNIQUE(start_at, end_at)

journal_activities     -- one card
  id, activity_key TEXT UNIQUE,          -- stable: sha of (day, start, title-norm)
  day TEXT, start_at, end_at, active_minutes REAL, state CHECK IN
  ('provisional','final'), title (1..120), summary, detailed_summary,
  category_id TEXT, category_confidence REAL,
  intention_id INTEGER NULL, intention_relation TEXT NULL, relation_confidence,
  app_primary TEXT, app_secondary TEXT,
  producer TEXT, prompt_version TEXT, model TEXT, window_id INTEGER,
  -- reserved for the post-MVP editable journal, unused now:
  user_title, user_category_id, user_locked INTEGER DEFAULT 0,
  created_at, updated_at

journal_activity_distractions
  id, activity_id FK CASCADE, start_at, end_at, title, summary

journal_activity_intervals   -- link to the deterministic ledger
  activity_id FK CASCADE, interval_key TEXT      -- key, not id: survives re-reconcile

journal_activity_evidence    -- sampled direct evidence for "View evidence"
  activity_id FK CASCADE, source_type CHECK IN ('frame','audio'), source_id, occurred_at
  UNIQUE(activity_id, source_type, source_id)
  + AFTER DELETE triggers on frames / audio_transcriptions (copy ledger pattern)

journal_categories     -- user-editable list; seeded on first run
  id TEXT PK, name, description, color_hex, is_system, is_idle, sort_order

focus_intentions       -- "what I am working on now"
  id, title, project TEXT NULL, started_at, ended_at NULL, source CHECK IN
  ('app','tray','mcp'), notes

focus_state            -- single current row, rewritten by the tail detector
  id CHECK (id = 1), computed_at, intention_id NULL, relation TEXT,
  confidence REAL, divergence_started_at NULL, dominant_task_title,
  evidence_ok INTEGER, reason TEXT

journal_runs           -- audit of every provider call (bounded, oldest pruned)
  id, window_id, kind CHECK IN ('cards','tail'), model, prompt_version,
  request_chars, response_chars, latency_ms, ok INTEGER, error, created_at

journal_state          -- checkpoint (pattern: activity_ledger_state)
  producer PK, last_window_end_at, updated_at
```

Work profile (role, projects, recurring activities) is small and user-edited;
store it in settings (`journalWorkProfile` JSON in the Rust `extra` map), not
in SQLite.

## 5. Journal pipeline (engine `crates/screenpipe-engine/src/journal/`)

Files: `mod.rs` (spawn + loop), `compile.rs` (deterministic), `idle.rs`,
`prompt.rs` (ported text, versioned), `schema.rs` (serde types +
`response_format` JSON schema), `validate.rs`, `llm.rs` (preset →
chat/completions, non-streaming), `time.rs` (shared idle constants),
`routes/journal.rs`, `routes/focus.rs`.

**Loop** (spawned from `create_router_inner`, `tokio::select!` on shutdown,
60 s tick, skips when `PowerManagerHandle` reports a pause reason or the
setting is off):

1. **Recover.** On startup set `processing` → `pending` for windows older than
   10 min (Dayflow never did this; roadmap requires it).
2. **Cut windows.** From `journal_state.last_window_end_at` to now, using
   ledger observations: split on > 2 min gap or when 15 min accumulate. The
   trailing, still-growing window is left uncut until it reaches 15 min or a
   5 min gap closes it. Insert `pending` rows; `UNIQUE(start,end)` makes
   retries idempotent.
3. **Per window, gate before the LLM.**
   - `reconcile_range` for the window so ledger intervals are fresh.
   - `< 5 min` observed → `skipped_short`.
   - **Idle rule** (port of `IdleBatchClassifier`, adapted): ≥ 90 % of the window
     has no `ui_events` and frames are near-identical (`content_hash`/`simhash`)
     → write one Idle card, status `idle`, no provider call. Merge with a
     preceding Idle card if the gap < 5 min.
   - `evidence_hash` unchanged since last `done` for the same range and same
     `prompt_version` → skip.
4. **Compile** (deterministic; the brief's stage 0): for each task-depth
   interval in `[end − 45 min, end]`: app, title, host/document, start/end,
   active minutes, ui-event counts (clicks/typing as intensity, never content),
   up to N text snippets from `frames.full_text` / `accessibility_text` chosen
   with `evenly_spaced_indices` and de-duplicated by diff against the previous
   snippet, audio presence (speaker count, no transcript text in v1). Hard
   budget ~12k chars per call; snippets shrink proportionally to interval time.
5. **Generate cards.** One `chat/completions` call, `response_format` JSON
   schema (Gemini schema from `GeminiDirectProvider+ActivityCards.swift:335`
   translated), system message "Return only the requested JSON". Inputs:
   previous cards in the horizon, new observations, category descriptors, work
   profile, current intention if any.
6. **Validate** (port `validateTimeCoverage`, `validateTimeline`,
   `ClaudeOutputValidator`): full coverage of observed ranges with 3 min
   tolerance, every non-final card ≥ 10 min, ≤ 60 min, no overlaps, no card
   bridging an evidence gap, categories snapped by `normalizeCategory`
   (exact → idle aliases → fallback). On failure append the ported correction
   block and retry; max 3 attempts; then write a `System` error card so the day
   has no hole and mark `failed`.
7. **Persist** in one `begin_immediate_with_retry` transaction: soft-replace
   cards overlapping the horizon (Dayflow `replaceTimelineCardsInRange`; keep
   `user_locked` rows untouched even though nothing sets it yet), link interval
   keys and sampled evidence, set `final` for cards ending before
   `now − 45 min`, advance `journal_state`. Provider calls never happen inside
   the transaction.

**Prompt port.** Use the Gemini card prompt as the base (merge-by-default,
10–60 min, distractions < 5 min, appSites, continuity rules) with the
Claude-variant strictness (fresh-segment mode when no card within 5 min, exact
rewrite bounds). Replace pixel instructions with text-evidence instructions
(app name and window title are authoritative fields, not read from a menu bar).
Keep the title/summary/detailed blocks as user-overridable settings with
Dayflow's defaults and banned-word lists. Version every prompt
(`prompt_version`); a bump invalidates cached windows lazily, never triggers a
mass regeneration on battery.

## 6. Distraction detection

**Categories.** Seed `journal_categories` from Dayflow's defaults (Work,
Personal, Distraction, Idle-system) and offer the role presets in settings.
`Distraction` is just a category name; there are no app or URL blocklists.

**Card classification.** The card prompt returns `category` and, when an
intention was active for the card's span, `intention_relation` +
`relation_confidence` + one-sentence `relation_reason`. Rules in the prompt
follow the roadmap: other work is not distraction; research supporting the task
is `supports_intention`; a break is a break; thin evidence → `unknown`.

**Intention.** `POST /focus/intentions` (title, project), `POST
/focus/intentions/{id}/end`, `GET /focus/intentions?active=true`. Set from the
journal header, the tray ("Set intention…" opens the journal), or MCP. At most
one active intention.

**Tail detector** (same worker, every tick, deterministic first):

- Read ledger intervals for the last 10 min. Dominant task = most active
  minutes. If no intention → `focus_state.relation = 'unknown'`, done.
- If the dominant task's category (from the most recent overlapping card) or
  its app/host matches what the intention has been supported by so far (apps
  and hosts seen in `supports_intention` cards for this intention) →
  `supports_intention`, reset `divergence_started_at`.
- Otherwise a divergence candidate. Ask the provider only when the candidate has
  persisted ≥ grace period (default 10 min) and not more than once per 5 min:
  small prompt with intention, work profile, last 10 min compiled observations
  → `{relation, confidence, reason}`. Persist to `focus_state` and
  `journal_runs`.
- Evidence check: if capture is stalled or the range is behind the history
  policy → `unknown` with `evidence_ok = 0`.

**Surfacing.** `GET /focus/status` returns `focus_state` + active intention.
Consumers: journal "now" strip, tray tooltip line (`tray.rs:2156` block) and a
disabled menu item near `recording_status`, MCP `focus-status`.

**Nudge (last milestone, optional).** Setting `focusNudgesEnabled` default
off. Fire through `commands::show_notification_panel` so the existing gate
(master, snooze, quiet hours) applies. Conditions, all required: setting on,
intention active, `possible_distraction` with confidence ≥ 0.8 persisting past
the grace period, `evidence_ok`, no meeting in progress, ≥ 30 min since the last
nudge. Body: "You set out to: <intention>. Last 12 min: <dominant task>." with
actions "Back to it" (opens the last evidence frame for the intention), "This
is fine" (records `other_work` and suppresses for this task for the session),
"Take a break" (records a break). No automatic actions.

## 7. HTTP API (oasgen-registered in `server.rs`, `#[oasgen]` + `OaSchema`)

| Route | Purpose |
|---|---|
| `GET /journal/day?date=YYYY-MM-DD` | Overview + cards for a local day (04:00 boundary): totals per category, focus vs distraction minutes, longest focus block (Dayflow `computeFocusBlocks`, 5 min gap), `data_status`, generation status of the last window |
| `GET /journal/activities/{id}?include_evidence=true` | One card, distractions, evidence with frame ids and timestamps |
| `GET /journal/status` | Worker state: enabled, preset ok, last window, pending count, last error |
| `POST /journal/regenerate?date=` | Reset windows of a day to `pending` (manual reprocess); rate-limited |
| `GET /journal/categories`, `PUT /journal/categories` | Category list |
| `GET /focus/status` | `focus_state` + active intention |
| `GET/POST /focus/intentions`, `POST /focus/intentions/{id}/end` | Intention lifecycle |

All routes are behind the existing auth middleware and history-access policy.
Query dates use `deserialize_flexible_datetime` where a range is accepted.

## 11. Evals and quality gates

- **Fixture corpus.** 10–20 real days exported as compiled observations JSON
  (no raw text beyond what the prompt would see), hand-labelled with expected
  card boundaries (±5 min), category, and, for days with an intention,
  relation. Store under `crates/screenpipe-engine/tests/fixtures/journal/`.
- **Metrics.** Coverage validity (100 % required), boundary agreement,
  category accuracy (target ≥ 80 %, roadmap's editable-label bar), distraction
  precision (target ≥ 90 %, roadmap's interruption bar, since the tail
  detector reuses it), `unknown` rate on stalled-capture days (must be 100 %),
  tokens per day and cost per provider.
- **Harness.** `cargo run -p screenpipe-engine --bin journal-eval -- --provider
  <preset> --fixtures ...` writing a Markdown report; TS format linter for MCP
  output like `evaluateDailySummaryFormat`. A prompt change does not merge
  without the report in the PR body.
- **Runtime budget.** Worker adds < 1 % average CPU and no allocation in
  capture paths (it reads the DB only). Provider calls: ~32–64 windows/day ×
  ~4–8k tokens; with a local model, zero cost; log actual numbers in
  `/journal/status`.

## 12. Risks and open decisions

1. **Provider fit.** Small local models may fail JSON coverage validation
   often; the correction loop caps at 3 and the error card keeps the day
   whole. Measure failure rate per provider in the eval.
2. **Ledger churn.** `reconcile_range` rewrites intervals; cards link by
   `interval_key` and keep their own evidence rows so re-reconciliation cannot
   orphan a card. Verify with a test that reconciles twice.
3. **Text volume.** Without diff-based snippet de-duplication the 45 min
   context does not fit; treat `compile.rs` as the critical component (brief
   §7 risk).
4. **False distraction labels erode trust.** Ship classification visibly but
   without nudges; enable nudges only after the eval meets the 90 % bar.
5. **Open:** report language (RU/EN toggle, default EN in code, prompt asks
   for the user's UI language); whether Idle cards show in the journal or
   collapse into gaps; whether audio transcript text may enter the card prompt
   in v1 (proposal: no, presence only).
